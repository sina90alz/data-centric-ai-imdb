# 📊 Data-Centric AI — IMDb Data Pipeline

A professional data-centric machine learning project focused on building a robust data pipeline using the IMDb reviews dataset.

This project emphasizes **data quality, validation, leakage detection, label issue detection, and reproducibility** rather than only model training.

---

## 🎯 Project Goals

- Build a production-quality ML data pipeline
- Practice data validation and profiling
- Detect and correct data leakage
- Implement deterministic data cleaning
- Find and flag mislabeled samples
- Detect near-duplicate text across train/test splits
- Understand dataset characteristics before modeling
- Prepare data for reliable downstream ML

---

## 🧠 Key Concepts Practiced

- Data ingestion from Hugging Face (`datasets` library)
- Schema validation (Great Expectations)
- Distribution analysis and profiling
- Exact and near-duplicate detection
- Data leakage detection and correction
- Text normalization and HTML artifact removal
- Mislabel detection (TF-IDF + Deep Learning approaches)
- Out-of-fold cross-validation for unbiased probabilities
- Reproducible pipelines with deterministic seeding
- Audit trails and report generation

## 🚀 Pipeline Steps & Execution Order

### 1️⃣ **Data Ingestion**

```bash
python -m scripts.01_ingest_imdb
```

**What it does:**
- Downloads `stanfordnlp/imdb` from Hugging Face
- Validates schema (requires `text` and `label` columns)
- Adds `id` and `source` columns for traceability
- Saves train and test as Parquet files

**Output:** `data/raw/imdb_train.parquet`, `data/raw/imdb_test.parquet`

---

### 2️⃣ **Data Profiling & Validation**

```bash
python -m scripts.02_validate_raw
```

**What it does:**
- Validates required columns and label values
- Computes statistics: nulls, length distributions (char/word counts)
- Detects exact text duplicates within each split
- **Detects data leakage:** exact text overlaps between train and test

**Key findings:**
- 96 duplicate texts in train, 199 in test
- **123 texts appear in both train and test** (leakage confirmed)

**Output:** `reports/validation_raw.md`

---

### 3️⃣ **Build Data Validation Suite (Great Expectations)**

```bash
python -m scripts.ge_01_build_suite_raw
```

**What it does:**
- Creates an expectation suite with schema and content constraints:
  - Exact column names and order
  - Non-null `text` and `label`
  - Labels strictly in {0, 1}
  - Row count between 20,000–30,000
  - Text length between 20–20,000 chars
  - Unique `id` values
- Saves suite to `gx/expectations/imdb_raw_suite.json`

**Output:** `gx/expectations/imdb_raw_suite.json`

---

### 4️⃣ **Validate with Great Expectations**

```bash
python -m scripts.ge_02_validate_raw
```

**What it does:**
- Loads the saved expectation suite
- Validates both train and test splits
- Generates human-readable report

**Output:** `reports/ge_validation_raw.md`, `reports/ge_validation_raw.json`

---

### 5️⃣ **Text Cleaning**

```bash
python -m scripts.03_clean_and_save
```

**What it does:**
- Applies `src.data.cleaning.clean_text()` to remove:
  - HTML tags (`<br>`, `<br/>`, `<br />`)
  - HTML entities (`&quot;`, `&amp;`)
  - Excess whitespace
- Saves cleaned text as new `text_clean` column
- **Preserves original `text`** for traceability

**Text normalization (intentional minimalism):**
- ✅ HTML artifact removal
- ✅ Whitespace normalization
- ❌ No lowercasing (preserves case for transformer models)
- ❌ No punctuation removal
- ❌ No stopword removal

**Output:** `data/processed/imdb_train_clean.parquet`, `data/processed/imdb_test_clean.parquet`

---

### 6️⃣ **Remove Data Leakage**

```bash
python -m scripts.04_remove_leakage.py
```

**What it does:**
- Detects exact text matches between train and test
- **Removes leaked rows from test set only** (conservative approach)
- Generates audit report with examples

**Key finding:** Removed 123 test rows (0.49%) that were exact duplicates of training samples

**Output:** `data/processed/imdb_test_noleak.parquet`, `reports/leakage_fix.md`

---

### 7️⃣ **Label Issue Detection (TF-IDF + Logistic Regression)**

```bash
python -m scripts.05_cleanlab_label_issues.py
```

**What it does:**
- Uses `cleanlab` library to find likely mislabeled samples
- Builds TF-IDF (max 30K features, bigrams) + LogisticRegression pipeline
- Runs 5-fold cross-validation to get out-of-fold predicted probabilities
- Flags rows where model predicts opposite label (likely mislabels)
- Exports ranked list by `label_quality` score (ascending = worst first)

**Key results:**
- 559 rows flagged as label issues (2.24% of 25,000 training rows)
- Top 20 suspicious examples shown in report

**Output:** `reports/cleanlab_label_issues.csv`, `.md`, `_summary.json`

---

### 8️⃣ **Label Issue Detection (DistilBERT)**

```bash
python -m scripts.06_cleanlab_distilbert_label_issues.py
```

**What it does:**
- Deep learning approach using `distilbert-base-uncased`
- Fine-tunes DistilBERT for 1 epoch per fold (5-fold CV)
- Collects out-of-fold predicted probabilities
- Applies `cleanlab.filter.find_label_issues()` on accumulated probabilities
- Handles GPU/CPU automatically (uses CUDA if available)

**Why separate from 05?**
- TF-IDF is fast but shallow; DistilBERT is slower but more accurate
- Both use proper out-of-fold CV to avoid overfitting signals
- Can run one or both depending on resources/time constraints

**Output:** `reports/cleanlab_distilbert_label_issues.csv`, `.md`, `_summary.json`

---

### 9️⃣ **Near-Duplicate Detection (Train vs. Test)**

```bash
python -m scripts.07_near_similarity_train_test.py
```

**What it does:**
- Computes TF-IDF vectors for all train + test texts
- Uses k-NN to find top-3 nearest neighbors in train for each test sample
- Flags test rows that are **semantically similar** (not just exact matches) to training data
- Useful for detecting copy-paste variations, paraphrases, near-duplicates
- Supports configurable similarity thresholds (default: 0.90 cosine similarity)

**Why needed?**
- Script 04 removes only exact text matches (123 rows)
- This script finds near-duplicates that might still cause evaluation bias
- Generates summary stats at multiple thresholds (0.85, 0.90, 0.95)

**Output:** `reports/train_test_near_similarity.csv`, `.md`, `_summary.json`

## 📈 Current Dataset Insights

- **Size:** 25,000 train + 25,000 test rows
- **Label distribution:** Perfectly balanced (50/50 pos/neg)
- **Text length:** Median ~174 words, ranges 10–2,470 words
- **Formatting:** HTML artifacts present (`<br>` tags)
- **Exact duplicates:** 96 in train, 199 in test
- **Leakage:** 123 test rows overlap with train (removed)
- **Label issues:** 559 rows (~2.2%) flagged as likely mislabeled
- **Near-duplicates:** Configurable detection available (script 07)

## 🔍 Key Design Decisions

| Feature | Approach | Rationale |
|---------|----------|-----------|
| **Text storage** | Keep both `text` and `text_clean` | Full auditability; can revert or compare |
| **Leakage handling** | Remove from test only, never train | Conservative; protects ground truth |
| **Label detection** | Two-layer (TF-IDF + DistilBERT) | Balance speed vs. accuracy |
| **Cross-validation** | Out-of-fold probabilities | Unbiased signal for label issue scoring |
| **Config** | Argparse defaults in scripts | Easy override without changing code |
| **Validation** | Great Expectations suite + reports | Contractual data validation; reusable |

## ⚠️ Known Gaps & Missing Items

1. **No `requirements.txt`** — dependencies not pinned; hard to reproduce environment
2. **No model training** — script 06 fine-tunes DistilBERT only for label detection, not for final deployment
3. **No evaluation script** — no inference or accuracy/F1 reporting on test set
4. **No pipeline runner** — no Makefile, DVC, or `run_all.py` to execute end-to-end
5. **No data versioning** — DVC not configured; data files in `data/` are git-ignored
6. **No logging** — scripts use `print()` instead of Python's `logging` module
7. **No unit tests** — `src/data/cleaning.py` has no test file
8. **No centralized config** — paths hardcoded as argparse defaults
9. **`data/eval/` unused** — mentioned in structure but never populated
10. **No experiment tracking** — no MLflow, W&B, or similar integration
11. **No CI/CD** — no GitHub Actions for automated validation

---

## ✅ What's Done Well

1. **Data-centric mindset** — every script focuses on understanding & improving data
2. **Efficient storage** — Parquet format with type safety
3. **Traceability** — `text_clean` column alongside original `text`
4. **Conservative fixes** — only removes from test, never train; audit reports document changes
5. **Two-layer label detection** — fast (TF-IDF) + accurate (DistilBERT) with proper OOF CV
6. **Great Expectations** — contractual validation with saved, reusable suite
7. **Reports committed** — findings preserved without re-running scripts
8. **Fail-fast errors** — scripts raise `ValueError` if preconditions violated
9. **Reproducible** — consistent `random_state=42` / `seed=42` throughout
10. **Modular code** — reusable `cleaning.py` in `src/` module
