## Purpose

This is a **learning project** focused on **data engineering techniques for deep learning**, specifically for NLP classification. The goal is NOT to train the best model — it is to build a production-quality data pipeline for the IMDb sentiment dataset. The emphasis is on data quality, validation, cleaning, leakage removal, and mislabeled-sample detection.

---

## Dataset

- **Source:** `stanfordnlp/imdb` from Hugging Face `datasets`
- **Task:** Binary sentiment classification (positive vs. negative movie reviews)
- **Splits:** `train` (25,000 rows), `test` (25,000 rows)
- **Columns after ingestion:** `id`, `text`, `label` (0=negative, 1=positive), `source` (split name)
- **Label distribution:** Perfectly balanced — 12,500 positive, 12,500 negative in both splits
- **Text characteristics:**
  - Train: chars min/p50/p95/max = 52 / 979 / 3432 / 13,704 — words min/p50/p95/max = 10 / 174 / 598 / 2,470
  - Test:  chars min/p50/p95/max = 32 / 962 / 3333 / 12,988 — words min/p50/p95/max = 4 / 172 / 582 / 2,278

## Pipeline Steps — Detailed

### Script 01 — `01_ingest_imdb.py`
**What it does:**
- Downloads `stanfordnlp/imdb` from Hugging Face using `datasets.load_dataset`
- Iterates over splits (`train`, `test`)
- Validates that `text` and `label` columns are present
- Adds `id` column (1-based integer row index) and `source` column (split name)
- Saves each split to Parquet under `data/raw/`

**Key design choices:**
- `--revision` arg allows pinning a specific dataset version for reproducibility
- Uses argparse for all paths — easy to override
- Raises `ValueError` if schema is unexpected (fail-fast)

**Output:** `data/raw/imdb_train.parquet`, `data/raw/imdb_test.parquet`

---

### Script 02 — `02_validate_raw.py`
**What it does:**
- Loads both raw Parquet files
- Checks that required columns `{id, text, label, source}` exist
- Validates labels are strictly in `{0, 1}`
- Computes: null count, empty string count, char/word length statistics (min, p50, p95, max), label value counts
- Detects exact text duplicates within each split
- Detects exact text overlap between train and test (data leakage signal)
- Writes a Markdown report

**Key findings from last run:**
- No nulls, no empty texts
- 96 duplicate texts in train, 199 in test
- 123 texts appear in both train and test (leakage confirmed)

**Output:** `reports/validation_raw.md`

---

### Script 03 — `03_clean_and_save.py`
**What it does:**
- Applies `src.data.cleaning.clean_text()` to the `text` column
- Saves result as a NEW column `text_clean` while KEEPING original `text` (for traceability/auditability)
- Reports how many rows changed and whether any became empty after cleaning

**Output:** `data/processed/imdb_train_clean.parquet`, `data/processed/imdb_test_clean.parquet`

---

### `src/data/cleaning.py` — `clean_text()` function
**What it does (text normalization):**
1. Handles `None` → returns `""`
2. Removes HTML `<br>`, `<br/>`, `<br />` tags (replaced with space)
3. Decodes HTML entities: `&quot;` → `"`, `&amp;` → `&`
4. Normalizes all whitespace sequences to a single space
5. Strips leading/trailing whitespace

**What it does NOT do (intentional minimalism):**
- No lowercasing (preserves case for transformer models)
- No punctuation removal
- No stopword removal
- No stemming/lemmatization

---

### Script 04 — `04_remove_leakage.py`
**What it does:**
- Computes exact text intersection between train and test sets
- Removes all 123 leaked rows from the **test** set (conservative: only modifies test, never train)
- Supports operating on `text` or `text_clean` column via `--use_clean_text` flag
- Writes markdown audit report with examples of removed overlapping texts

**Key finding:** 123 test rows (0.49%) were exact duplicates of training samples. These were removed to produce a clean eval set.

**Output:** `data/processed/imdb_test_noleak.parquet`, `reports/leakage_fix.md`

---

### Script 05 — `05_cleanlab_label_issues.py`
**What it does:**
- Classical ML approach to finding mislabeled samples
- Builds a `TfidfVectorizer(max_features=30000, ngram_range=(1,2))` + `LogisticRegression` pipeline
- Wraps it in `CleanLearning` from the `cleanlab` library
- Uses 5-fold cross-validation internally to generate out-of-fold predicted probabilities
- `cl.get_label_issues()` returns a DataFrame flagging likely mislabeled rows
- Joins back to original data to get text, saves ranked by `label_quality` score (ascending = worst first)
- Exports CSV, JSON summary, and Markdown report with top 20 suspicious examples

**Key results:**
- 25,000 training rows analyzed
- 559 rows flagged as likely label issues (2.24% issue rate)
- Model disagreed: e.g. a clearly positive review labeled 0, or a clearly negative labeled 1

**Output:** `reports/cleanlab_label_issues.csv`, `reports/cleanlab_label_issues_summary.json`, `reports/cleanlab_label_issues.md`

---

### Script 06 — `06_cleanlab_distilbert_label_issues.py`
**What it does:**
- Deep learning approach to finding mislabeled samples (more accurate than TF-IDF)
- Uses `distilbert-base-uncased` as feature extractor + classifier
- Implements 5-fold `StratifiedKFold` manually
- Each fold: fine-tunes DistilBERT for 1 epoch on fold's train portion, predicts on validation portion
- Collects out-of-fold predicted probabilities (`pred_probs` array of shape [25000, 2])
- Applies `cleanlab.filter.find_label_issues()` on accumulated probabilities to identify suspicious rows
- Handles GPU/CPU automatically (uses CUDA if available)
- Frees GPU memory between folds to avoid OOM
- Tokenizes with `max_length=256`, padding

**Key design choices:**
- Uses `save_strategy="no"` to avoid disk bloat from checkpoint saving
- `report_to="none"` to suppress W&B/wandb logging
- Uses `softmax_np()` custom implementation (not `scipy`) to convert logits to probabilities
- 1 epoch per fold is intentionally light (can increase for better precision)

**Output:** `reports/cleanlab_distilbert_label_issues.csv`, `.md`, `.json`

---

### Script ge_01 — `ge_01_build_suite_raw.py`
**What it does:**
- Builds a Great Expectations expectation suite called `imdb_raw_suite`
- Uses `ge.from_pandas(df)` (in-memory, not datasource-based)
- Defines expectations:
  - `expect_table_columns_to_match_ordered_list(["id","text","label","source"])`
  - `expect_column_values_to_not_be_null("text")` and `("label")`
  - `expect_column_values_to_be_in_set("label", [0,1])`
  - `expect_table_row_count_to_be_between(20000, 30000)`
  - `expect_column_value_lengths_to_be_between("text", 20, 20000)`
  - `expect_column_values_to_be_unique("id")`
- Saves suite to `gx/expectations/imdb_raw_suite.json`
- Builds GE Data Docs (HTML report)

**Output:** `gx/expectations/imdb_raw_suite.json`

---

### Script ge_02 — `ge_02_validate_raw.py`
**What it does:**
- Loads the saved `imdb_raw_suite` expectation suite from GE context
- Validates both train and test DataFrames against the suite
- Serializes full GE result to JSON and a human-readable Markdown summary
- Reports which expectations passed/failed per split

**Output:** `reports/ge_validation_raw.json`, `reports/ge_validation_raw.md`

## Known Gaps / Missing Items

These items are intentionally not yet implemented but represent natural next steps:

1. **No `requirements.txt` or `pyproject.toml`** — dependencies are not pinned; hard to reproduce the environment
2. **No model training script** — `06_cleanlab_distilbert_label_issues.py` fine-tunes DistilBERT only for label issue detection (not for final deployment). There is no `07_train_final_model.py`
3. **No evaluation script** — no script that runs inference on `imdb_test_noleak.parquet` and reports accuracy, F1, confusion matrix
4. **No pipeline runner** — no `Makefile`, `dvc.yaml`, or `run_all.py` script to execute the full pipeline end-to-end in one command
5. **No actual data versioning** — README mentions "data versioning mindset" but DVC is not configured; data files in `data/` are gitignored and not tracked
6. **No logging** — all scripts use `print()` instead of Python's `logging` module; no log files
7. **No unit tests** — `src/data/cleaning.py` has no test file (e.g. `tests/test_cleaning.py`)
8. **No centralized config** — paths are hardcoded as argparse defaults scattered across scripts; no single `config.yaml` or `constants.py`
9. **`data/eval/` directory** — mentioned in README structure but never created or used by any script
10. **README is outdated** — shows only 3 scripts in the pipeline section; does not mention scripts 04–06 or the GE scripts
11. **No experiment tracking** — no MLflow, Weights & Biases, or similar integration for tracking runs
12. **No CI/CD** — no GitHub Actions workflow to run validation checks automatically on data changes

## What Is Done Well

1. **End-to-end data-centric mindset** — every script focuses on understanding and improving data quality, not just training a model
2. **Parquet format** — efficient columnar storage, type-safe, supports schema inspection
3. **Traceability** — `text_clean` column added alongside original `text` so every transformation is auditable
4. **Conservative leakage fix** — only removes from test set, never from train; audit report documents exactly what was removed
5. **Two-layer label issue detection** — light TF-IDF baseline (fast) + heavy DistilBERT (accurate); both use proper out-of-fold cross-validation probabilities
6. **Great Expectations integration** — contractual validation with a saved, reusable suite (not just ad-hoc asserts)
7. **All reports committed to repo** — `reports/` folder is in version control so findings are preserved without re-running
8. **Fail-fast error handling** — scripts raise `ValueError`/`FileNotFoundError` immediately if preconditions are violated
9. **Seed control** — `random_state=42` / `seed=42` used consistently for reproducibility
10. **Separate `src/` module** — `cleaning.py` logic is importable and reusable, not buried in a script

## Important Notes for AI Assistants

- The `data/` directory is NOT in the repository — do not generate code that assumes these files are present without running `01_ingest_imdb.py` first
- Script 06 is GPU-optional but very slow on CPU for 25,000 samples × 5 folds
- GE is used in "in-memory" mode (no datasource connector), so `great_expectations.yml` has `datasources: {}`
- The project uses `from_pandas` GE API which is the legacy V2 API (not the newer Fluent datasource API)
- `cleanlab` >= 2.x has a different API from v1.x — `CleanLearning` is in `cleanlab.classification`, `find_label_issues` is in `cleanlab.filter`
